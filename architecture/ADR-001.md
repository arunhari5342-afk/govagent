# ADR-001: Agentic Architecture and Framework Choice

## Status

Accepted

## Date

2026-09-22

## Context

GovAgent is a governed enterprise helpdesk and policy assistant.

The system needs to:

* Answer questions using enterprise knowledge
* Retrieve relevant documents
* Maintain conversation context
* Select and use approved tools
* Handle multi-step tasks
* Apply validation and guardrails
* Support auditability and observability
* Prevent uncontrolled agent behavior

A purely conversational LLM is insufficient because enterprise operations require explicit control over retrieval, tools, authorization, validation, and execution flow.

## Decision

GovAgent will use a **workflow-oriented agent architecture**.

The architecture will separate responsibilities into:

1. Plain application code
2. Controlled workflows
3. Agent/LLM reasoning
4. Retrieval services
5. Approved tools
6. Governance and validation
7. Observability

The initial orchestration framework will be **LangGraph**.

Standard Python application components will handle deterministic functionality such as API endpoints, database operations, retrieval, validation, tool implementation, and logging.

## Why a Workflow-Oriented Agent Architecture?

A workflow-oriented architecture provides explicit control over how an agent executes.

For an enterprise system, the application should be able to define boundaries such as:

```text
Input
 ↓
Validation
 ↓
Agent
 ↓
Tool Authorization
 ↓
Tool
 ↓
Agent
 ↓
Guardrails
 ↓
Output Validation
 ↓
Response
```

This makes important execution steps visible and testable.

## Framework Choice

### LangGraph

LangGraph is selected for the initial agent orchestration layer because the project requires:

* Explicit state and workflow transitions
* Multi-step agent execution
* Tool calling
* Conditional routing
* Human-in-the-loop capability as a future extension
* Better control over agent execution
* Ability to combine deterministic nodes with agent nodes

## Alternatives Considered

### Plain LLM Chain

A simple LLM chain could handle basic question answering.

However, the project requires controlled routing, tools, validation, and multi-step execution. A simple chain would not represent the complete agentic workflow as clearly.

### LangChain Agent

LangChain provides useful abstractions for LLM and tool integration.

It can be used within the project, but the architecture requires explicit workflow/state control, making LangGraph more suitable for the orchestration layer.

### CrewAI

CrewAI focuses on multi-agent collaboration.

GovAgent's MVP does not require multiple autonomous agents. Introducing multi-agent collaboration at the beginning would add complexity before the core governed workflow is established.

### Fully Autonomous Multi-Agent System

A fully autonomous design would provide significant flexibility but would make governance, debugging, authorization, and evaluation more difficult for the initial prototype.

## Consequences

### Positive

* Clear separation between agents, workflows, and code
* Explicit execution flow
* Easier testing of individual components
* Controlled tool execution
* Better foundation for guardrails
* Easier observability
* Future support for human approval and more complex workflows

### Negative

* More architecture and implementation effort than a simple LLM chain
* Workflow state must be designed carefully
* Additional framework dependency
* Developers must understand both agent behavior and workflow behavior

## Governance Consideration

The framework does not provide governance automatically.

GovAgent will therefore implement governance explicitly through:

* Input validation
* Output validation
* Tool authorization
* Tool allowlists
* Guardrail checks
* Audit logging
* Evaluation

The LLM will not be given unrestricted access to enterprise operations.

## Decision Summary

GovAgent will use:

```text
Python
  +
FastAPI
  +
LangGraph
  +
LLM
  +
Retrieval
  +
Approved Tools
  +
Validation / Guardrails
  +
Observability
```

The design intentionally keeps deterministic operations in normal application code and uses agent reasoning only where reasoning is required.
